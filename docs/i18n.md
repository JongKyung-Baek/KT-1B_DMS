# 다국어 운영 가이드

## 현재 지원 언어

- 한국어: `ko` (기본 언어)
- 영어: `en`
- 인도네시아어: `id`

브라우저의 `Accept-Language`를 기본값으로 사용한다. 예를 들어 브라우저가
`id-ID`를 보내면 애플리케이션은 이를 `id`로 정규화하여 인도네시아어 화면을
표시한다. 로그인 화면과 로그인 후 상단 언어 선택기에서 `lang=ko`, `lang=en`,
`lang=id`를 직접 선택할 수도 있으며 선택값은 세션에 유지된다.

## 번역 리소스

- 화면 문구: `src/main/webapp/messages/feature*.properties`
- 공통 문구: `src/main/webapp/messages/message*.properties`
- DB 기반 메뉴·그리드·폼·툴바·콤보 문구: `DOCS_LANG`
- jqGrid 언어 파일: `src/main/resources/static/js/i18n/grid.locale-*.js`

JavaScript 번들 로더는 지역 태그를 언어 코드로 정규화한다. 따라서 `id-ID`와
`id_ID`도 `feature_id.properties`, `message_id.properties`를 불러온다.

## 패키지 번들과 DB 번역 병합

시작 시 `CommonMessageContainer`는 먼저 WAR에 포함된
`message_<language>.properties`를 읽고, 같은 언어의 `DOCS_LANG` 값을 그 위에
덮어쓴 뒤 런타임 번들을 만든다. 이 순서 덕분에 DB에 일부 번역만 있어도 패키지의
완전한 번들이 사라지지 않으며, 운영 중 관리한 DB 번역은 같은 키에 우선 적용된다.

`indonesian_locale_ddl.sql`은 패키지의 인도네시아어 공통 번들 전체, 최신 활성
메뉴와 현재 메타데이터가 참조하는 DB 전용 키를 `DOCS_LANG`에 등록한다. 이후
새로 추가된 DB 전용 키에 아직 `id`
번역이 없는 경우에만 그리드·폼·툴바·콤보가 영문 번역을 사용하고, 영문도 없을
때는 원래 DB 문구를 사용한다. 새 메뉴나 공통 문구를 추가할 때는 정적 번들과
같은 마이그레이션 또는 새 후속 마이그레이션에 `LANG_TYPE='id'` 행을 함께
추가한다.

## 새 언어 추가 절차

1. `LocaleUtil.SUPPORTED_LANGUAGES`에 언어 코드를 추가한다.
2. `feature_<language>.properties`와 `message_<language>.properties`를 만들고 기존
   한국어·영어 번들과 동일한 키를 번역한다.
3. `DOCS_LANG`에 활성 메뉴 번역을 먼저 추가하고, 그리드·폼·툴바·콤보 번역을
   순차적으로 추가한다.
4. 로그인 화면과 로그인 후 언어 선택기에 새 언어 항목을 추가한다.
5. 번들 키 동등성, 브라우저 자동 감지, `lang` 수동 선택, 로그인 후 메뉴와 주요
   화면을 테스트한다.

번역 파일과 DB 행을 UTF-8로 저장한다. 번역 검토가 끝나지 않은 언어를 지원 목록에
먼저 노출하면 한 화면에 여러 언어가 섞일 수 있으므로, 최소한 전체 화면 번들과 활성
메뉴 번역을 준비한 뒤 선택기에 공개한다.
